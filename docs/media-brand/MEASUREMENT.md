### Weekly operator workflow

1. Use a fixed reporting timezone and complete windows. Record date, site commit and the assets actually released. Use the native dashboards for Search Console, Substack and YouTube if accessible. Export aggregates only. Keep the reports in the private editorial hub and the public template blank.
2. Map articles and media back to their canonical source slugs. Use explicit “unavailable” for metrics without a data source, “suppressed” for small cells and “zero” only when a valid measurement supports it. Do not report newsletter open rates as readership; mail-client proxies distort them.
3. For distribution now, use ordinary canonical URLs. If a privacy review approves referral labelling later, use a small fixed set such as `utm_source=youtube`, `utm_medium=video`, `utm_campaign=observer_pilot`, `utm_content=workforce` for the same canonical path. Never encode audience, email, account, or unique click identifiers. Do not change canonical tags or store raw URL queries. One code per asset, not per subscriber. Use origin-only referrer groups first if sufficient.
4. Compare the same period after each release, record confounders (age of article, reach, promotion and corrections) and choose one follow-up. At low volumes use reader observations and raw aggregate counts instead of significance claims.

### Decision before any collection

The lowest-change option is to continue with existing platform aggregates and no new site collection. If additional data is needed, compare an aggregate self-hosted option with the already-used hosting provider's [Web Analytics privacy description](https://vercel.com/docs/analytics/privacy-policy). Vercel describes a daily visitor hash and configurable captured fields; verify current details for the actual product and plan. No-cookie does not itself settle GDPR or ePrivacy requirements.

Before activating a provider or changing event handling, have the publisher document the purpose, controller and processor roles, applicable legal basis, any required consent and withdrawal path, provider terms/DPA and transfer terms, data fields, storage, deletion and access. See [GDPR Articles 5, 6, 13, 25 and 28](https://eur-lex.europa.eu/eli/reg/2016/679/oj) and the [EDPB technical scope guidance on ePrivacy Article 5(3)](https://www.edpb.europa.eu/our-work-tools/our-documents/guidelines/guidelines-22023-technical-scope-art-53-eprivacy-directive_en). Apply local implementation and obtain appropriate review. Prefer no individual identifiers, no fingerprinting, no full referrer paths or queries, minimal geography, minimum retention supported by the provider, and access limited to the publisher. Suppress slices with fewer than five observations in shared reports. A documented 28-day baseline and monthly aggregate retention may suffice; set a short event retention and verify deletion.

If approved, reuse the existing adapter. Allow only canonical public paths, coarse campaign labels and fixed event names. Start with pageviews, feature click, and Substack outbound click. Test with synthetic data on an isolated preview: one event per action, network payload contains only expected fields, no network request before required consent or after withdrawal, consent settings persist appropriately, and a missing configuration sends nothing. Update the public privacy notice before activation and keep a disable switch. No analytics code, settings, tracking parameters or new collection were activated for this change.
